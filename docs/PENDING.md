## 3. 构建脚本的一个脆弱点：括号深度扫描不认字符串

**现象（2026-10-19 真实踩到）**

`tools/build.py` / `tools/build-plugin.py` 的 `top_level_decls()` 用「逐行累加 `{` `}` 净数」
判断当前是不是顶层。如果**数据文件里的字符串**含花括号（哪怕完全合法），
深度就会漂移，后面声明的常量会被当成「源码里不存在」：

```
[vocab-study] CORE_EXPORTS 里登记了源码中不存在的符号：ETD.ETYM_COVERAGE
```

**当时的处理**：改生成器（`tools/make-etym.py` 的 `FORBIDDEN_RE`），
让数据文本里**永远不出现** `{ } < > | = [ ]`，并把不合规条目整条丢掉。
这是对的（数据本来也不该带模板残留），但只是**绕开**，不是修好。

**要做的**：把 `top_level_decls()` 改成按字符扫描、跳过 `'…'` `"…"` `` `…` `` 字符串与
`//` `/* */` 注释，再数花括号。改完请用一份含花括号字符串的假数据验证一次。
